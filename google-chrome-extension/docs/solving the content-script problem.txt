Is it possible to write content scripts as Modules in any way?

I had an idea that by having the user launch the script from an extension action, i could launch content scripts from the serviceworker on the action and bypass the ES6 limitation this way.
For this, first a chrome.action.onClicked would be registered in the service-worker with a function. Then, the function would call chrome.scripting.executeScript with a specific function.

Unfortunately, it looks the idea doesn't work and the injected scripts would still act like normal content-scripts registered in the manifest.
This is because, according to ChatGPT XDDD, scripting.executeScript basically loads the function as string and runs it then, all context from the service-worker is lost.

Basically, service-worker is a completely separated domain in the backstage that never sees the document DOM, only the content-scripts see the DOM but don't see into the backstage.
The two can only communicate via chrome's built in message api or connection ai.
message api: chrome.runtime.sendMessage on the content side and chrome.runtime.onMessage.addListener on service side.
port api: port = chrome.runtime.connect(); port.postMessage(); on content side and on service side: chrome.runtime.onConnect.addListener (and the closing listeners too probably)

These are the only benefits of dynamically loading content-scripts inside the service-worker based on user invocation, instead of in manifest:
1) The extension doesn't have to ask for all pages permission;
2) The web page(s) which the content-script would launch on, and the content script(s) itself/themselves, can be dynamically decided.
3) Optimisation from not having to run the script all the time.

This is based on chrome extensions official documentation and some querying from chatgpt. The claims made by chatgpt have been specifically highlighted in the text.

Custom script injection

Dynamic content-script injection has one potential other benefit, a custom injector could be written that collects all necessary files based on something fixed like folder structure or something and injects them.
To allow to import things from other folders, not only subfolders, some sort of marking would have to be added to each script file, meaning which files they depend on.
If to go really dumb, could write them as Modules and the custom injector converts them from Modules to normal scripts during runtime.
And with this we basically arrive at bundlers.

Is it possible to use TypeSCript?

TypeScript would make code much more readable.
But it introduces the need to compile cause chrome can't read ts files.
So for example using the tsc compiler, then refer chrome to dist/service-worker.js and dist/content.js for example.
